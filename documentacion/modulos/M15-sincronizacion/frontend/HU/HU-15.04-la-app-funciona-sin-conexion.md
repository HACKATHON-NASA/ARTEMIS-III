## Cola offline (`resources/js/offline/`)

**`db.ts`: esquema Dexie** (base `astrohealth`, versión 1):

| Almacén | Clave e índices | Contenido |
|---|---|---|
| `cola_envios` | `id`, índices `user_id`, `creado_en` | `{ id, user_id, endpoint, metodo, cuerpo, multipart, creado_en, intentos, siguiente_intento_en, ultimo_error }` |
| `rechazados` | `id`, índice `user_id` | Lo mismo más `{ estado_http, mensaje, rechazado_en }` |
| `instantaneas` | `url` | `{ url, componente, props, guardada_en, user_id }` |
| `credenciales` | `user_id` | `{ user_id, token, expira_en }` |

**`cola.ts`:**

| Función | Comportamiento |
|---|---|
| `encolar(endpoint, cuerpo, { multipart } = {})` | Guarda el elemento con el `user_id` actual (`cuerpo.id` ya generado por la página con `crypto.randomUUID()`), y llama a `procesar()` si hay red |
| `procesar()` | Uno a uno, en orden de `creado_en`, **solo los del usuario con sesión** y token vigente. Respuesta según la [tabla del backend](../../backend/HU/HU-15.04-la-app-funciona-sin-conexion.md): quita, pasa a `rechazados`, pausa (`401`) o reintenta con espera de 1, 2, 4… hasta 60 s |
| Cuándo se procesa | Al abrir la app, con el evento `online`, cada 60 s con red y después de cada `encolar` |
| Un solo procesador | Un bloqueo (Web Locks API, `navigator.locks.request('cola', …)`) evita que dos pestañas envíen lo mismo a la vez |
| Orden de dependencias | Un elemento cuyo `endpoint` contiene el `id` de otro aún en la cola (la foto de un síntoma) espera a que ese otro se envíe |

**`clienteApi.ts`:** `fetch` con `Authorization: Bearer <token>` desde `credenciales`. Con `multipart`, arma un `FormData` (los `Blob` de las fotos).

**`instantaneas.ts`: consulta sin conexión con Inertia.** La ficha no decía cómo se hace:

| Paso | Detalle |
|---|---|
| Guardar | `router.on('success', e => …)` guarda `{ url, componente, props }` de las páginas de consulta de F1 (lista fija `PAGINAS_OFFLINE`: inicio, vitales, sueño, exámenes, tests, radiación, ejercicio, nutrición, y los formularios de captura) |
| Precargar | Tras iniciar sesión con red, se piden en segundo plano esas URL con `fetch` y el encabezado `X-Inertia: true` (Inertia devuelve el JSON de la página) y se guardan. Así un formulario se puede abrir sin red aunque nunca se haya visitado |
| Mostrar sin red | `router.on('exception')` (error de red al navegar): si hay instantánea de esa URL, se muestra con `router.push({ url, component, props: { ...props, sinConexion: { desde: guardada_en } } })`, que en Inertia 2 cambia de página **sin pedir nada al servidor**. Si no hay, una página "Sin conexión: esta pantalla aún no está disponible sin red" |
| Aviso | Las páginas con `sinConexion` muestran arriba "Datos de hace N min (sin conexión)" |

**Service Worker** (`vite-plugin-pwa`, `registerType: 'autoUpdate'`): precarga JS, CSS y fuentes, y como *fallback* de navegación sirve la última página de F1 cacheada. **No** cachea respuestas de la API.

## `IndicadorSincronizacion.vue` (cabecera de F1)

| Estado | Texto |
|---|---|
| Sin pendientes ni rechazados | ✔ "Sincronizado" |
| Pendientes | ⟳ "3 pendientes" (y ⊘ "Sin conexión" si no hay red) |
| Rechazados | ⚠ "1 rechazado" |
| Al tocarlo | Panel con los pendientes (tipo y hora) y los rechazados (con su mensaje y el botón "Descartar") |

## Accesibilidad

- El indicador anuncia los cambios con `aria-live="polite"` ("3 registros pendientes de envío").

## Criterios de aceptación

- **Dado** la red desactivada, **cuando** completo un PVT, registro un síntoma con foto y cargo un examen, **entonces** quedan 4 elementos en `cola_envios` (la foto después del síntoma); **y al** volver la red, llegan una sola vez y en orden.
- **Dado** un `422`, **cuando** se procesa, **entonces** el elemento pasa a `rechazados` con el mensaje, y el indicador muestra "1 rechazado".
- **Dado** un `401`, **cuando** se procesa, **entonces** la cola se pausa y se pide iniciar sesión sin perder nada.
- **Dado** dos pestañas abiertas, **cuando** las dos procesan, **entonces** cada elemento se envía una vez.
- **Dado** que visité "Mis signos vitales" con red, **cuando** la abro sin red, **entonces** veo sus datos con "Datos de hace N min (sin conexión)".
- **Dado** que nunca abrí "Registrar síntoma" pero inicié sesión con red, **cuando** lo abro sin red, **entonces** funciona (precarga).
