## Especificación

**Migración `create_paquetes_recibidos`** (cola de **recepción**, en los dos nodos)

| Columna | Definición en Laravel | Notas |
|---|---|---|
| `id` | `$table->uuid('id')->primary();` | El mismo del paquete de origen: idempotencia de recepción |
| `tipo`, `prioridad` | Como en `paquetes_sync` | |
| `payload` | `$table->longText('payload');` | |
| `comprimido` | `$table->boolean('comprimido')->default(false);` | |
| `estado` | `$table->string('estado', 12);` | `en_transito` (solo en la nave, mientras no se cumple el retardo), **`recibido`** (pendiente de importar), `procesado` o `error` |
| `error` | `$table->text('error')->nullable();` | **Nueva.** Mensaje si la importación falla (el paquete no se pierde y se puede reintentar) |
| `intentos` | `$table->unsignedSmallInteger('intentos')->default(0);` | **Nueva** |
| `entrega_programada_en` | `$table->dateTime('entrega_programada_en', 3)->nullable();` | |
| `recibido_en`, `procesado_en` | `$table->dateTime(..., 3)` (`procesado_en` nulo) | |

- **Índices:** `(estado, prioridad, recibido_en)` (importación en orden) y `(estado, entrega_programada_en)`.
- El estado `recibido` es **nuevo**: la Tierra **guarda** los paquetes al recibirlos y los **importa después**, en segundo plano. La ficha los importaba dentro de la petición, y 2.000 paquetes no caben en el tiempo de una petición de cPanel.

**Migración `create_ventanas_enlace`** (solo en la nave)

| Columna | Definición en Laravel | Notas |
|---|---|---|
| `id` | `$table->uuid('id')->primary();` | |
| `inicio`, `fin` | `$table->dateTime(..., 3);` | |
| `motivo` | `$table->string('motivo', 15);` | `conjuncion` o `manual` |
| `created_at`, `updated_at` | `$table->datetimes(3);` | `fin` cambia con `sync:cerrar-ventana` |

- **Índice:** `(inicio, fin)`.
