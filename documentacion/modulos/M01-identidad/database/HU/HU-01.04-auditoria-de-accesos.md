## Parte A (Sprint 1) · Migración `create_auditoria`

| Columna | Definición en Laravel | Tipo en MySQL | Notas |
|---|---|---|---|
| `id` | `$table->uuid('id')->primary();` | `char(36)` | La genera el servidor (`HasUuids`); se conserva al importarse en la Tierra |
| `user_id` | `$table->unsignedBigInteger('user_id')->nullable();` | `bigint unsigned NULL` | `NULL` si actuó un dispositivo, un nodo o la consola, o si el inicio de sesión fallido no corresponde a ningún usuario |
| `actor` | `$table->string('actor', 150);` | `varchar(150) NOT NULL` | **Copia** legible de quién actuó en ese momento: el correo del usuario, `dispositivo:<identificador>`, `nodo:<nombre>` o `consola`. En la Tierra permite leer las entradas de la nave aunque el usuario no exista allí |
| `token_id` | `$table->unsignedBigInteger('token_id')->nullable();` | `bigint unsigned NULL` | Token de Sanctum usado, si aplica |
| `accion` | `$table->string('accion', 20);` | `varchar(20) NOT NULL` | *Enum* `AccionAuditoria`: `login`, `login_fallido`, `logout`, `ver`, `crear`, `anular`, `modificar`, `exportar` |
| `recurso_tipo` | `$table->string('recurso_tipo', 60);` | `varchar(60) NOT NULL` | Ej.: `users`, `tokens`, `umbrales`, `lineas_base`, `sesion` |
| `recurso_id` | `$table->string('recurso_id', 36)->nullable();` | `varchar(36) NULL` | |
| `tripulante_id` | `$table->uuid('tripulante_id')->nullable();` | `char(36) NULL` | Tripulante cuyos datos se tocaron |
| `detalle` | `$table->json('detalle')->nullable();` | `json NULL` | Datos extra **no clínicos**: `motivo`, `antes` y `despues` de un cambio de catálogo o parámetro (M16). Nunca contraseñas, tokens ni valores de salud |
| `ip` | `$table->string('ip', 45)->nullable();` | `varchar(45) NULL` | `NULL` cuando no hay petición HTTP (consola o cola) |
| `nodo_origen` | `$table->string('nodo_origen', 6);` | `varchar(6) NOT NULL` | `nave` o `tierra` |
| `ocurrido_en` | `$table->dateTime('ocurrido_en', 3);` | `datetime(3) NOT NULL` | UTC |

- **Sin `timestamps`** (`public $timestamps = false;`) y sin `updated_at`.
- **Índices:** `(tripulante_id, ocurrido_en)`, `(user_id, ocurrido_en)` y `(ocurrido_en)`.
- **Sin claves foráneas.** Todas las referencias son lógicas ([ficha §3](../README.md#3-relaciones)).
- **Modelo `Auditoria`:** `use HasUuids;`, `$timestamps = false`, `$dateFormat = 'Y-m-d H:i:s.v'`, `casts` con `accion => AccionAuditoria::class` y `ocurrido_en => 'datetime'`. Los eventos `updating` y `deleting` lanzan `AuditoriaInmutableException`.

**Protección en la base (sustituye a "quitar `UPDATE` y `DELETE` al usuario de MySQL").** En cPanel los permisos se dan a toda la base de datos, y MySQL no permite quitar a una tabla un permiso concedido a nivel de base. Por eso la misma migración crea dos *triggers* que rechazan cualquier `UPDATE` o `DELETE`, incluidos los que no pasan por el modelo (`Auditoria::query()->update(...)`):

```sql
-- mysql
CREATE TRIGGER auditoria_sin_update BEFORE UPDATE ON auditoria
FOR EACH ROW SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'auditoria es de solo insercion';
CREATE TRIGGER auditoria_sin_delete BEFORE DELETE ON auditoria
FOR EACH ROW SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'auditoria es de solo insercion';

-- sqlite (pruebas)
CREATE TRIGGER auditoria_sin_update BEFORE UPDATE ON auditoria
BEGIN SELECT RAISE(ABORT, 'auditoria es de solo insercion'); END;
CREATE TRIGGER auditoria_sin_delete BEFORE DELETE ON auditoria
BEGIN SELECT RAISE(ABORT, 'auditoria es de solo insercion'); END;
```

- La migración elige la variante con `DB::getDriverName()` y la ejecuta con `DB::unprepared()`.
- **Si cPanel no deja crear *triggers*** (falta el permiso `TRIGGER`), la migración captura la `QueryException`, escribe `Log::warning('auditoria: sin triggers', ...)` y **continúa**. Queda la protección del modelo.
- El comando `php artisan identidad:verificar-auditoria` imprime "Protección de auditoría: activa (2 triggers)" o "Protección de auditoría: SOLO EN LA APLICACIÓN" (MySQL: `SHOW TRIGGERS LIKE 'auditoria'`).
- `down()`: `DROP TRIGGER IF EXISTS` de los dos y después `Schema::dropIfExists('auditoria')`.

**Volumen:** del orden de cientos de filas al día (una por página de datos ajenos, una cada 10 minutos como máximo por usuario, recurso y tripulante, más inicios y cierres de sesión). No se purga.

## Parte B (Sprint 3, dentro de HU-15.01) · Migración `create_auditoria_envios`

Guarda qué horas de auditoría de la nave ya se encolaron hacia la Tierra. Hace falta una tabla aparte porque `auditoria` no admite `UPDATE`, así que no se puede marcar cada fila como "enviada".

| Columna | Definición en Laravel | Tipo en MySQL | Notas |
|---|---|---|---|
| `hora` | `$table->dateTime('hora')->primary();` | `datetime NOT NULL` | Inicio de la hora en UTC, con minutos y segundos en cero (ej.: `2026-11-03 14:00:00`) |
| `n_entradas` | `$table->unsignedInteger('n_entradas');` | `int unsigned NOT NULL` | Puede ser 0 (la hora se marca igual, para avanzar) |
| `encolado_en` | `$table->dateTime('encolado_en', 3);` | `datetime(3) NOT NULL` | |

Solo se escribe en el nodo `nave`. Es de solo inserción; no necesita *triggers*.

## Criterios de aceptación

- **Dado** una fila de `auditoria`, **cuando** ejecuto `DB::table('auditoria')->update(['accion' => 'ver'])`, **entonces** la base lanza un error y la fila no cambia (con SQLite en las pruebas y con MySQL en local).
- **Dado** una fila de `auditoria`, **cuando** llamo a `$fila->delete()`, **entonces** se lanza `AuditoriaInmutableException`.
- **Dado** que guardo una entrada a las `14:05:07.123`, **cuando** la leo, **entonces** `ocurrido_en` conserva los milisegundos (`.123`).
- **Dado** los dos nodos de cPanel, **cuando** ejecuto `php artisan identidad:verificar-auditoria`, **entonces** el resultado se anota en la revisión del Sprint 1 (activa o solo en la aplicación).
- **(Parte B) Dado** que la hora `14:00` ya está en `auditoria_envios`, **cuando** se intenta insertar otra vez, **entonces** la clave primaria lo impide.
