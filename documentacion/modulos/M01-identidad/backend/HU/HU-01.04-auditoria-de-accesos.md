## Parte A · Especificación

**1. Contrato `Identidad\Contratos\RegistroAuditoria`.**

```php
public function registrar(
    AccionAuditoria $accion,
    string $recursoTipo,
    ?string $recursoId = null,
    ?string $tripulanteId = null,
    ?int $userId = null,      // solo para quien actúa sin petición HTTP (listeners en cola); si es null, se toma de la petición
    ?array $detalle = null,   // datos extra no clínicos: motivo y antes/después de un cambio de configuración (M16)
): void;
```

Quién actuó y desde dónde se toma así:

| Contexto | `user_id` | `actor` | `token_id` | `ip` |
|---|---|---|---|---|
| Petición con sesión | `auth()->id()` | correo del usuario | `NULL` | `request()->ip()` |
| Petición con token de dispositivo | `NULL` | `dispositivo:<identificador>` | `id` del token | `request()->ip()` |
| Petición con token de nodo | `NULL` | `nodo:<nombre>` | `id` del token | `request()->ip()` |
| Petición con token de la PWA | `id` del usuario dueño | correo del usuario | `id` del token | `request()->ip()` |
| Sin petición (consola o cola), con `$userId` | `$userId` | correo de ese usuario si existe en este nodo; si no, `usuario:<id>` | `NULL` | `NULL` |
| Sin petición y sin `$userId` | `NULL` | `consola` | `NULL` | `NULL` |

`nodo_origen = config('app.nodo')` y `ocurrido_en = now()` en UTC con milisegundos.

**2. Reglas para `ver`** (solo para esta acción):

| # | Regla |
|:---:|---|
| 1 | Solo se registra si los datos son de un tripulante **distinto** al del usuario (`ConsultaTripulantes::porUsuario`), o de toda la tripulación (`tripulante_id = null`) |
| 2 | **No** se registra si la petición es una recarga parcial de Inertia: lleva el encabezado `X-Inertia-Partial-Data` o `X-Inertia-Partial-Except` (lo que envía `usePoll`) |
| 3 | No se registra si ya existe una entrada `ver` con el mismo `user_id`, `recurso_tipo`, `recurso_id` y `tripulante_id` (comparando `NULL` con `NULL`) en los **últimos 10 minutos** |

Las demás acciones (`crear`, `anular`, `modificar`, `exportar`, `login`…) se registran siempre.

**3. Quién llama a `registrar`.**

| Origen | Acción | Dónde |
|---|---|---|
| Evento `Illuminate\Auth\Events\Login` | `login` (`recurso_tipo = sesion`) | Listener de M01 |
| Evento `Logout` | `logout` | Listener de M01 |
| Evento `Failed` | `login_fallido`; `user_id` si el correo existe; `actor` = el correo intentado, recortado a 150 caracteres. **Nunca** se guarda la contraseña | Listener de M01 |
| `UmbralModificado` (M16) | `modificar`, `recurso_tipo = umbrales`, `recurso_id = umbral_id`, `$userId = modificado_por`. **Se ignora** si el evento llega con `importado = true` (campo que rellena M15 al construir el evento durante una importación), porque ese cambio ya se auditó en el nodo donde ocurrió. Mientras M15 no exista, el campo vale `false` | Listener de M01. M16 **no** llama a `RegistroAuditoria` para los umbrales, para no duplicar la entrada |
| HU-01.02 y HU-01.03 | `crear`, `modificar`, `anular` sobre `users` y `tokens` | Casos de uso de M01 |
| Cada página o exportación de otro módulo que muestra datos de salud de otro tripulante | `ver` o `exportar` | El controlador de ese módulo, en su propia historia |

**4. Ruta web** `GET /admin/auditoria` (Gate `ver-auditoria`): 50 entradas por página, de la más reciente a la más antigua. Filtros en la URL, todos opcionales:

| Filtro | Validación | Aplica |
|---|---|---|
| `tripulante` | código `T1`…`T9` existente | `tripulante_id` (traducido con `ConsultaTripulantes::porCodigo`) |
| `actor` | texto ≤ 150 | `actor LIKE %texto%` |
| `accion` | valor de `AccionAuditoria` | igualdad |
| `nodo` | `nave` o `tierra` | `nodo_origen` |
| `desde`, `hasta` | fecha `Y-m-d`, con `desde ≤ hasta` | `ocurrido_en` entre `desde 00:00:00.000` y `hasta 23:59:59.999` UTC |

*Props*: `entradas` (con `actor`, `ip` nula y `detalle`), `filtros` y `tripulantes` (códigos para el filtro, de `ConsultaTripulantes`). Abrir esta página **no** genera auditoría.

## Parte B · Especificación (Sprint 3, dentro de HU-15.01)

**5. Envío a la Tierra** (solo con `APP_NODO=nave`). Comando `identidad:encolar-auditoria`, programado con `->hourlyAt(5)->withoutOverlapping()`:

1. Hora inicial: la siguiente a la última de `auditoria_envios`; si la tabla está vacía, la hora de la primera entrada de `auditoria`.
2. Para cada hora completa hasta la hora anterior a la actual (como máximo 48 horas por ejecución):
   1. Toma las entradas con `nodo_origen = 'nave'` y `ocurrido_en` en `[hora, hora + 1 h)`.
   2. En **una transacción**: si hay entradas, `ColaSincronizacion::encolar('auditoria', 3, ['hora' => …, 'entradas' => [...]])`. Después inserta la fila de `auditoria_envios`, aunque haya 0 entradas.
3. En el nodo `tierra` el comando termina sin hacer nada.

**6. Importador** (`ImportadorAuditoria`, implementa `Sincronizacion\Contratos\Importador`):
- `tipo()` devuelve `'auditoria'`.
- `importar($payload)` hace `insertOrIgnore` de cada entrada **con su mismo `id`** y todos sus campos, incluidos `nodo_origen = 'nave'`, `user_id` y `actor`. Un paquete repetido no duplica nada.
- `exportar($id)` recibe una hora (`2026-11-03T14`) y devuelve el mismo *payload* del punto 5. Solo existe para cumplir la interfaz.

## Criterios de aceptación

**Parte A**
- **Dado** el CMO (T1), **cuando** abre una página con datos de T2 que llama a `registrar(ver, ...)`, **entonces** se crea una entrada `ver` con `tripulante_id` de T2 y `actor = cmo@astrohealth.test`.
- **Dado** el astronauta T2, **cuando** abre sus propios datos, **entonces** no se crea ninguna entrada.
- **Dado** el CMO, **cuando** se hacen 10 recargas parciales de la misma página, **entonces** no se crea ninguna entrada nueva.
- **Dado** el CMO, **cuando** abre dos veces la misma página de T2 en menos de 10 minutos, **entonces** hay una sola entrada; **y a los 11 minutos** (`travel(11)->minutes()`), **entonces** se crea otra.
- **Dado** un intento de inicio de sesión con contraseña incorrecta, **cuando** se registra, **entonces** hay una entrada `login_fallido` y ninguna columna contiene la contraseña.
- **Dado** que el médico de vuelo edita un umbral en la Tierra, **cuando** se publica `UmbralModificado`, **entonces** se crea **una** entrada `modificar` sobre `umbrales`.
- **Dado** el admin, **cuando** filtra `/admin/auditoria` por `accion=login` y por un rango de fechas, **entonces** solo ve esas entradas.
- **Dado** un usuario sin `ver-auditoria`, **cuando** abre `/admin/auditoria`, **entonces** recibe `403`.

**Parte B**
- **Dado** 3 entradas de la nave entre las 14:00 y las 14:59, **cuando** se ejecuta el comando a las 15:05, **entonces** se encola un paquete `auditoria` de prioridad 3 con las 3 entradas y `auditoria_envios` tiene la hora `14:00`.
- **Dado** que el comando no se ejecutó durante 5 horas, **cuando** vuelve a ejecutarse, **entonces** encola las 5 horas pendientes, sin huecos.
- **Dado** el mismo paquete importado dos veces en la Tierra, **cuando** se consulta `auditoria`, **entonces** cada entrada aparece una vez, con `nodo_origen = nave`.
