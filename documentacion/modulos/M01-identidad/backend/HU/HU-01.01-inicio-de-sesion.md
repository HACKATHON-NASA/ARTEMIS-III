## Especificación

**1. Comprobaciones al iniciar sesión.** Se hacen **después** de validar la contraseña y **en este orden**; la primera que falla corta el proceso, cierra la sesión recién abierta y devuelve el error en el campo `email` (`ValidationException::withMessages`):

| # | Condición | Mensaje (exacto) |
|:---:|---|---|
| 1 | Correo o contraseña incorrectos | El del *starter kit* traducido: "Estas credenciales no coinciden con nuestros registros." |
| 2 | `rol = sistema` | El mismo de la fila 1 (no se revela que el usuario existe) |
| 3 | `activo = false` | "Este usuario está desactivado. Contacte con la administración." |
| 4 | El rol no trabaja en este nodo (tabla siguiente) | `nave` → "Este usuario trabaja en el nodo Tierra." · `tierra` → "Este usuario trabaja en la nave." |

| `APP_NODO` | Roles que pueden iniciar sesión |
|---|---|
| `nave` | `astronauta`, `cmo`, `ingeniero_biomedico`, `admin` |
| `tierra` | `medico_vuelo`, `investigador`, `ingeniero_biomedico`, `admin` |

La tabla vive en un solo lugar: `Rol::puedeIniciarSesionEn(string $nodo): bool`. El límite de 5 intentos por minuto del *starter kit* se conserva.

**2. Sesión.**
- `SESSION_LIFETIME=480` (8 h de inactividad) y `SESSION_EXPIRE_ON_CLOSE=false`.
- **Se quita "Recordarme":** el *login* ignora el campo `remember`. Una *cookie* de recordar dura años y anularía las 8 h.

**3. Middleware del grupo `web`** (para usuarios con sesión, en este orden):

| Middleware | Qué hace |
|---|---|
| `UsuarioActivo` | Si `activo = false`: `Auth::guard('web')->logout()`, invalida la sesión, regenera el token CSRF y redirige a `/login` con el error "Este usuario está desactivado. Contacte con la administración." |
| `RolPermitidoEnNodo` | Si el rol actual no trabaja en este nodo (por ejemplo, porque el admin le cambió el rol): cierra la sesión igual que el anterior, con el mensaje de la fila 4 |

**4. Inicio de cada rol.** La redirección tras el *login* va siempre a `/inicio` (se ignora `intended()`, para no llevar a nadie a una página que su rol no puede ver). `/inicio` la atiende `RedirigirSegunRol`:

| Rol | Redirige a |
|---|---|
| `astronauta`, `cmo` | `/astronauta` |
| `medico_vuelo` | `/tierra` |
| `ingeniero_biomedico`, `admin` | `/admin` |
| `investigador` | `/admin/exportaciones` |

La ruta `dashboard` del *starter kit* se elimina, o redirige a `/inicio`.

**`RedirigirSegunRol` conserva el *flash*** (`$request->session()->reflash()`) antes de redirigir. Sin eso, el *flash* que deja el inicio de sesión (`tokenPwa` de HU-15.04, avisos) se consume en `/inicio` y **nunca llega** a la página del rol.

**5. Páginas temporales del Sprint 0.** Rutas `GET` que devuelven `Inertia::render('<App>/Inicio')`, protegidas por rol, que cada módulo reemplaza en su sprint:

| Ruta | Página | Roles |
|---|---|---|
| `/astronauta` | `Astronauta/Inicio` | `astronauta`, `cmo` |
| `/cmo` | `Cmo/Inicio` | `cmo` |
| `/tierra` | `Tierra/Inicio` | `medico_vuelo` |
| `/admin` | `Admin/Inicio` | `ingeniero_biomedico`, `admin` |
| `/admin/exportaciones` | `Admin/Exportaciones/Index` | `investigador` |

**6. Props compartidas (`HandleInertiaRequests::share`).**

```php
'auth' => ['user' => $user ? ['id' => $user->id, 'name' => $user->name, 'rol' => $user->rol->value] : null,
           'permisos' => $user ? GatesIdentidad::queCumple($user) : []],
'nodo' => config('app.nodo'),                              // 'nave' | 'tierra'
'tripulante' => fn () => app()->bound(ConsultaTripulantes::class) && $user
                         ? /* { id, codigo } del usuario o null */ : null,
'mision' => fn () => app()->bound(ConsultaMision::class) ? /* { nombre, dia_mision, perfil_enlace } */ : null,
'flash' => ['exito' => session('exito'), 'error' => session('error'), 'tokenPwa' => session('tokenPwa'),
            'descargarUrl' => session('descargarUrl')],          // M14: reporte recién generado
```

- **Sprint 0:** M02 todavía no existe, así que `tripulante` y `mision` valen `null`. La comprobación `app()->bound(...)` evita el error 500 y se mantiene después, porque es inofensiva.
- `config('app.nodo')` se lee de `APP_NODO`. Si falta o no vale `nave` o `tierra`, la aplicación **no arranca** (excepción en `AppServiceProvider::boot()` con el mensaje "APP_NODO debe ser 'nave' o 'tierra'").

**7. Cierre de sesión.** `POST /logout` (del *starter kit*), sin cambios en esta historia. La revocación del token de la PWA al salir se añade en [HU-15.04](HU-15.04-token-de-la-pwa.md).

**8. Ajustes del *starter kit*.** Se conserva solo el **cambio de contraseña** (y la apariencia, si viene). Se quitan **borrar cuenta** (ruta `DELETE` de `settings/profile` o `profile.destroy`, y el componente `DeleteUser`) y la edición de nombre y correo: ningún usuario se borra y el correo se copia en `auditoria.actor`; esos datos los cambia el admin.

## Criterios de aceptación

- **Dado** el nodo `nave`, **cuando** `astronauta@astrohealth.test` inicia sesión con su contraseña, **entonces** llega a `/astronauta`.
- **Dado** el nodo `nave`, **cuando** `medico@astrohealth.test` inicia sesión con su contraseña correcta, **entonces** ve "Este usuario trabaja en el nodo Tierra." y no queda con sesión.
- **Dado** el nodo `tierra`, **cuando** `astronauta@astrohealth.test` inicia sesión, **entonces** ve "Este usuario trabaja en la nave.".
- **Dado** cualquier nodo, **cuando** `nodo-nave@astrohealth.internal` intenta iniciar sesión, **entonces** ve el mensaje de credenciales incorrectas.
- **Dado** un usuario inactivo, **cuando** inicia sesión con su contraseña correcta, **entonces** ve "Este usuario está desactivado. Contacte con la administración.".
- **Dado** un usuario con sesión abierta, **cuando** el admin lo desactiva, **entonces** su siguiente petición lo lleva a `/login` con ese mensaje.
- **Dado** cada uno de los 6 roles en su nodo, **cuando** inicia sesión, **entonces** llega al inicio de la tabla del punto 4.
- **Dado** que envío `POST /register`, **cuando** responde el servidor, **entonces** devuelve `404`.
- **Dado** un usuario con sesión, **cuando** envía la petición de borrar su cuenta del *starter kit*, **entonces** recibe `404` y el usuario sigue existiendo.
- **Dado** un *flash* `exito` puesto al iniciar sesión, **cuando** pasa por `/inicio`, **entonces** llega a la página del rol.
- **Dado** que envío `remember=1` al iniciar sesión, **cuando** responde el servidor, **entonces** no se crea la *cookie* `remember_web_*`.
- **Dado** el Sprint 0 (sin M02), **cuando** un astronauta abre `/astronauta`, **entonces** la página carga con `tripulante: null` y `mision: null`.
