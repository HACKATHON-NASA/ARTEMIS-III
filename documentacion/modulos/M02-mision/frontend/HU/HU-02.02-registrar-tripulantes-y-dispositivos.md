
**Props** (las de la ficha, más `soloLectura: boolean`)

```ts
{
  tripulantes: { id: string, codigo: string, nombre: string, sexo: 'F' | 'M', fecha_nacimiento: string,
                 rol_a_bordo: string, usuario: { id: number, email: string } | null }[],
  usuariosDisponibles: { id: number, email: string, rol: 'astronauta' | 'cmo' }[],   // activos y sin tripulante en la misión activa
  soloLectura: boolean
}
```

| Elemento | Especificación |
|---|---|
| Aviso de usuarios sin tripulante | Solo si `usuariosDisponibles` no está vacío. Icono ⚠ + "N usuarios astronauta o CMO sin tripulante: <correos separados por coma>" y la línea "Vincúlelos editando un tripulante." |
| Columna "Edad" | Calculada en el navegador a partir de `fecha_nacimiento` |
| Columna "Usuario" | Correo, o "— Sin usuario" |
| Panel de alta y edición | Panel lateral derecho (480 px; pantalla completa en móvil). Campos: "Código" (solo en el alta; ayuda "T1 a T9. No se podrá cambiar."), "Nombre", "Sexo" (botones de opción "Femenino" y "Masculino"), "Fecha de nacimiento", "Rol a bordo" y "Usuario vinculado" (desplegable con "Sin usuario" + `usuariosDisponibles` + el usuario actual, si lo hay). Botones "Cancelar" · "Crear tripulante" o "Guardar cambios" |
| En la edición | El código se muestra como texto ("T2"), no como campo |
| Éxito | "Tripulante guardado." |
| Sin misión | `EstadoVacio`: "Primero cree la misión." con el enlace "Ir a Misión" |

```
│ …            │  Dispositivos                                       [+ Nuevo dispositivo] │

│              │                                                                           │
```

**Props** (las de la ficha, con `estado_sensor` que puede ser `null` y `soloLectura`)

```ts
{
  dispositivos: { id: string, identificador: string, tipo: TipoDispositivo,
                  asignado_a: { tipo: 'tripulante' | 'modulo', codigo: string, de_mision_activa: boolean } | null,
                  bateria_pct: number | null, ultimo_contacto_en: string | null,
                  estado_sensor: 'ok' | 'revisar_colocacion' | 'sin_datos' | null }[],   // null hasta HU-03.03
  tripulantes: { id: string, codigo: string }[],
  modulosNave: { id: string, codigo: string, nombre: string }[],
  tipos: TipoDispositivo[],
  soloLectura: boolean
}
```

| Elemento | Especificación |
|---|---|
| Columna "Batería" (`EstadoDispositivo.vue`) | Barra de 5 segmentos **y** el número ("82 %"). Con menos del 20 %, además, icono ⚠. Sin dato: "—" |
| Columna "Último contacto" | Relativo ("hace 3 min", "hace 2 h"), con la fecha completa en `title`. Sin dato: "Nunca" |
| Columna "Estado" | Icono + texto: ✓ "Correcto", ⚠ "Revisar colocación", ○ "Sin datos". **Si `estado_sensor` es `null` en todas las filas (antes de HU-03.03), la columna y su filtro no se muestran** |
| En la Tierra | Batería y último contacto muestran "—" con `title` "Disponible en la nave" (esos campos no se sincronizan) |
| Refresco | `usePoll(30000, { only: ['dispositivos'] })`. Solo en la nave |
| Panel de alta | "Tipo" (desplegable con los textos de la tabla de valores) → según el tipo aparece **un solo** selector: "Tripulante" (tipos personales), "Módulo de la nave" (`monitor_ambiental`), "Asignar a" con las opciones "Nadie", "Tripulante" y "Módulo" (`tableta`) o ninguno (`simulador`, con el texto "El simulador no se asigna: envía datos en nombre de todos los dispositivos."). Después, "Identificador" con ayuda "Letras, números y guiones (p. ej., oximetro-T5). No se podrá cambiar." y un valor sugerido según la [convención](../../database/HU/HU-02.02-registrar-tripulantes-y-dispositivos.md) (`<tipo>-<código>`), que se puede editar |
| Panel de edición | Identificador y tipo como texto; solo se cambia la asignación |
| Dispositivo de la misión anterior | Si `asignado_a.de_mision_activa` es `false`: en "Asignado a", ⚠ + "Misión anterior (T2)" y, en el panel, el aviso "No envía datos hasta que lo asigne a un tripulante o módulo de esta misión." |
| Reasignación | Al cambiar el tripulante de un dispositivo personal: diálogo "¿Reasignar <identificador> a <T nuevo>?" con el texto "Las lecturas anteriores seguirán siendo de <T anterior>. El token del dispositivo no cambia." y los botones "Cancelar" · "Reasignar" |
| Éxito | "Dispositivo guardado." |

## Mensaje en F1 sin tripulante vinculado

Si un `astronauta` o `cmo` entra en F1 y `tripulante` es `null`, el *layout* de M01 muestra `EstadoVacio` con este texto exacto ([backend de M02 §3.2](../../backend/README.md#32-tripulantes-y-usuarios)): **"Tu usuario no está vinculado a ningún tripulante; avisa al administrador."** Lo implementa HU-01.01 (M01) y se prueba aquí, cuando ya existe la vinculación.

## Criterios de aceptación

- **Dado** el formulario de alta de dispositivo, **cuando** elijo "Oxímetro", **entonces** solo aparece el selector "Tripulante"; **y con** "Monitor ambiental", solo "Módulo de la nave".
- **Dado** que elijo "Oxímetro" y T5, **cuando** miro el identificador, **entonces** sugiere `oximetro-T5`.
- **Dado** un dispositivo con 18 % de batería, **cuando** se muestra, **entonces** se ven la barra, "18 %" y el icono ⚠.
- **Dado** el Sprint 1 (sin HU-03.03), **cuando** se abre la página, **entonces** no aparece la columna "Estado".
- **Dado** `usuariosDisponibles` con `ana@…`, **cuando** se abre Tripulantes, **entonces** aparece el aviso con su correo; **y en** el desplegable "Usuario vinculado" de cualquier tripulante aparece `ana@…`.
- **Dado** el ingeniero biomédico, **cuando** mira su menú, **entonces** ve "Dispositivos" pero no "Tripulantes" ni "Misión".
- **Dado** una pantalla de 375 px, **cuando** abro Dispositivos, **entonces** cada dispositivo es una tarjeta y no hay desplazamiento horizontal.
