## Especificación

Esta historia crea las dos tablas que usan los **tres** tests (PVT, aritmética y memoria).

**Migración `create_sesiones_test`**

| Columna | Definición en Laravel | Notas |
|---|---|---|
| `id` | `$table->uuid('id')->primary();` | Generado en el cliente |
| `tripulante_id` | `$table->uuid('tripulante_id');` | Lógica (M02) |
| `tipo` | `$table->string('tipo', 12);` | `pvt`, `aritmetica` o `memoria` |
| `inicio` | `$table->dateTime('inicio', 3);` | |
| `duracion_s` | `$table->unsignedSmallInteger('duracion_s');` | |
| `completa` | `$table->boolean('completa');` | **La decide el servidor** (backend), no el cliente |
| `origen` | `$table->string('origen', 10);` | `app` o `simulador` |
| `metricas` | `$table->json('metricas')->nullable();` | Calculadas en el servidor. `NULL` si la sesión está incompleta |
| `completada_en` | `$table->dateTime('completada_en', 3);` | Fin de la sesión (`inicio` + `duracion_s`) |
| `created_at` | `$table->dateTime('created_at', 3);` | Llegada al servidor |

- **Índice:** `(tripulante_id, tipo, completa, inicio)`.
- El número de sesión **no se guarda**: se calcula con `ROW_NUMBER() OVER (PARTITION BY tripulante_id, tipo ORDER BY inicio)` sobre las completas (MySQL 8). En las pruebas con SQLite (3.25+, que también admite funciones de ventana) funciona igual.

**Migración `create_respuestas_item`**

| Columna | Definición en Laravel | Notas |
|---|---|---|
| `id` | `$table->uuid('id')->primary();` | Lo genera el servidor (`HasUuids`) |
| `sesion_id` | `$table->foreignUuid('sesion_id')->constrained('sesiones_test')->restrictOnDelete();` | |
| `orden` | `$table->unsignedSmallInteger('orden');` | 1, 2, 3… |
| `estimulo` | `$table->string('estimulo', 20);` | PVT `luz`; aritmética `47+28`; memoria `58291` |
| `respuesta` | `$table->string('respuesta', 20)->nullable();` | |
| `es_correcta` | `$table->boolean('es_correcta')->nullable();` | **La recalcula el servidor** en aritmética y memoria; `NULL` en el PVT |
| `tiempo_ms` | `$table->unsignedInteger('tiempo_ms')->nullable();` | **Ahora admite `NULL`**: en el PVT, toque antes del estímulo (sin tiempo de reacción) o estímulo sin respuesta en 30 s |
| `es_falsa_salida` | `$table->boolean('es_falsa_salida')->default(false);` | Solo PVT |
| `sin_respuesta` | `$table->boolean('sin_respuesta')->default(false);` | **Nueva.** Solo PVT: el estímulo llegó al tiempo máximo (`pvt_espera_max_s`) sin respuesta. Cuenta como lapso |
| `presentado_en` | `$table->dateTime('presentado_en', 3);` | |

- **Única:** `(sesion_id, orden)`.
- Sin `created_at` (la tiene la sesión).

**Parámetro nuevo en `parametros_mision` (M16)**, que esta historia añade al *seeder* de parámetros de M16: `pvt_espera_max_s` = `30` (segundos que espera un estímulo del PVT antes de contarlo como lapso sin respuesta; parámetro de diseño †).

## Criterios de aceptación

- **Dado** una sesión con 30 ítems, **cuando** se guarda, **entonces** hay 1 fila en `sesiones_test` y 30 en `respuestas_item`, en la misma transacción.
- **Dado** un PVT con una falsa salida antes del estímulo, **cuando** se guarda, **entonces** ese ítem tiene `es_falsa_salida = 1` y `tiempo_ms = NULL`.
- **Dado** sesiones de T2 con `inicio` 3, 1 y 2 de noviembre (llegadas en ese orden), **cuando** se consulta el número de sesión, **entonces** la del 1 es la 1.ª, la del 2 la 2.ª y la del 3 la 3.ª.
