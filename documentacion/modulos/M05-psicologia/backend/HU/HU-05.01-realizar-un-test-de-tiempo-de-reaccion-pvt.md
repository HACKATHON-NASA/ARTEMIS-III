## Especificación

**1. `POST /api/v1/psicologia/sesiones`.** Esta historia construye el endpoint, la validación común y las métricas del PVT. HU-05.02 y HU-05.07 solo añaden su tipo.

```json
{ "id": "uuid", "tripulante_id": "T2", "tipo": "pvt", "inicio": "2026-11-03T08:00:00.000Z", "duracion_s": 180,
  "completa": true,
  "items": [ { "orden": 1, "estimulo": "luz", "respuesta": null, "es_correcta": null, "tiempo_ms": 274,
               "es_falsa_salida": false, "sin_respuesta": false, "presentado_en": "2026-11-03T08:00:04.512Z" } ] }
```

**2. Validación común** (`SesionRequest`):

| Campo | Regla |
|---|---|
| `id` | UUID |
| `tipo` | `pvt`, `aritmetica` o `memoria` |
| `inicio` | ISO 8601, no más de 5 minutos en el futuro |
| `duracion_s` | Entero 1–600 |
| `items` | 1 a 200 elementos; `orden` 1, 2, 3… sin huecos ni repetidos |
| `items.*.presentado_en` | ISO 8601 entre `inicio` y `inicio + duracion_s` (+1 s de margen) |
| `completa` | Booleano. Se recibe, pero **lo decide el servidor** |

**3. Ítems del PVT:** `estimulo = "luz"`; `respuesta` y `es_correcta` nulos. Cada ítem es una de tres cosas:

| Caso | `tiempo_ms` | `es_falsa_salida` | `sin_respuesta` |
|---|---|---|---|
| Respuesta al estímulo | 0 – 30.000 | El servidor la pone en `true` si `tiempo_ms < 100` | `false` |
| Toque **antes** del estímulo | `null` | `true` | `false` |
| Sin respuesta en `pvt_espera_max_s` (30 s) | `null` | `false` | `true` |

**4. Métricas del PVT** (`Domain/Reglas/CalculadoraMetricasPvt.php`, clase pura). Se usan los **tiempos válidos**: respuestas al estímulo con `tiempo_ms ≥ 100`.

| Clave | Cálculo |
|---|---|
| `mediana_tr_ms` | Mediana de los tiempos válidos (sin falsas salidas). Con número par, media de los dos centrales. Redondeada a 1 decimal |
| `desviacion_tr_ms` | Desviación estándar muestral de los tiempos válidos, 1 decimal |
| `lapsos` | Tiempos válidos > 500 ms **+** ítems `sin_respuesta` |
| `falsas_salidas` | Ítems con `es_falsa_salida` (antes del estímulo o < 100 ms) |
| `n_validas` | Número de tiempos válidos |

**5. `completa` del PVT:** `duracion_s ≥ pvt_duracion_s` (180) **y** `n_validas ≥ 10`. Si no se cumple, se guarda con `completa = false` y `metricas = NULL`, aunque el cliente dijera `true`.

**6. Guardado:** en una transacción, la sesión y sus ítems. Si el `id` ya existe → `200` con la sesión guardada, sin tocar nada. Respuesta `201`: `{ id, completa, metricas }`.

**7. Evento:** si `completa`, `TestCognitivoCompletado` (`sesion_id`, `tripulante_id`, `tipo`, `numero_sesion` (`ROW_NUMBER` en ese momento), `metricas`, `completada_en`) después de confirmar. Las incompletas no publican nada.

**8. Página `GET /astronauta/tests/pvt`** (Gate `ver-datos-propios`): *props* `{ duracionS, intervaloMinS, intervaloMaxS, esperaMaxS }` desde M16.

## Criterios de aceptación

- **Dado** tiempos válidos [250, 260, 270, 280, 650] y una falsa salida antes del estímulo, **cuando** se calculan, **entonces** `mediana_tr_ms = 270`, `lapsos = 1` y `falsas_salidas = 1`.
- **Dado** un ítem con `tiempo_ms = 80`, **cuando** se calcula, **entonces** cuenta como falsa salida y no entra en la mediana, aunque el cliente dijera `es_falsa_salida = false`.
- **Dado** un ítem `sin_respuesta`, **cuando** se calcula, **entonces** suma un lapso y no entra en la mediana.
- **Dado** un PVT con `completa = true` y `duracion_s = 120`, **cuando** se guarda, **entonces** queda incompleto, sin métricas y sin evento.
- **Dado** la misma sesión dos veces, **cuando** llega la segunda, **entonces** responde `200` y no hay ítems duplicados.
- **Dado** el token del simulador sin `tripulante_id`, **cuando** envía, **entonces** responde `422`; **y con** el token de `astroskin-T2`, `403`.
- **Dado** el token PWA de T2 con `tripulante_id = T3` en el cuerpo, **cuando** envía, **entonces** la sesión queda a nombre de T2.
