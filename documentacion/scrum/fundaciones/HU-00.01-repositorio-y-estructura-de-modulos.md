# HU-00.01 · Repositorio con el *starter kit* y la estructura de módulos

> [← Fundaciones](README.md) · [Plan de sprints](../plan-de-sprints.md#3-sprint-0--fundaciones) · Siguiente: [HU-00.03 · Librería de componentes](HU-00.03-libreria-de-componentes.md)

**Como** equipo de desarrollo, **quiero** un repositorio con el *starter kit* de Laravel (Vue, Inertia y Tailwind v4) y la estructura de los 16 módulos, **para** empezar todos sobre la misma base.

| Prioridad | Sprint | Depende de | Pts |
|---|:---:|---|:---:|
| Must | 0 | — | 3 |

Es la primera historia: **ninguna otra puede empezar sin ella**. Deja la base vacía pero lista. No crea tablas, pantallas ni lógica de ningún módulo, y tampoco instala Sanctum (eso lo hace [HU-01.01](../../modulos/M01-identidad/database/HU/HU-01.01-inicio-de-sesion.md)).

## Especificación

**1. Repositorio.** Un solo repositorio, con la estructura de [03 §7](../../docs/propuesta/03-propuesta-tecnologica.md#7-estructura-del-repositorio):

```
ArtemisIII/
├── README.md            # Cómo instalar y ejecutar (punto 7)
├── documentacion/       # Lo que ya está escrito: docs, modulos, scrum, herramientas
├── astrohealth/          # Proyecto Laravel + Vue, con docs/ para la documentación técnica del código

└── .github/workflows/   # CI (HU-00.02)
```

Rama principal `main`, protegida: solo se fusiona por *pull request* con una revisión.

**2. Crear el proyecto Laravel** dentro de `astrohealth/` con el instalador oficial, opciones **Vue**, autenticación **propia de Laravel** (no WorkOS) y pruebas con **Pest**. Se usa la última versión estable de Laravel y del *starter kit*, y la versión de PHP que exija debe existir en el cPanel (comprobarlo antes en el panel de los dos subdominios, porque HU-00.04 depende de eso).

**Las carpetas ya están creadas** (19 de octubre): los 16 módulos, en el backend (`app/Modules/<Modulo>/`, con todas sus capas) y en el frontend (`resources/js/modules/<Modulo>/`), más `app/Shared` y las carpetas globales del frontend. Cada carpeta tiene su `README.md` ([estructura de carpetas](../../modulos/00-arquitectura/10-estructura-de-carpetas.md)). Esta historia añade el código que hace que cada módulo cargue:

```
app/Modules/<Modulo>/
├── <Modulo>ServiceProvider.php
├── routes.php            # Vacío (con un comentario) hasta la primera historia del módulo
└── Tests/Feature/<Modulo>CargaTest.php
```

**5. Cómo se carga un módulo.** Sin paquetes de módulos de terceros:

| Pieza | Cómo |
|---|---|
| Espacio de nombres | `App\Modules\<Modulo>\...`. Ya funciona con el `autoload` de `composer.json` (`App\` → `app/`): no hay que tocarlo |
| *ServiceProvider* | Cada uno se registra en `bootstrap/providers.php` |
| Rutas | En `boot()`: `Route::group([], __DIR__.'/routes.php')`, **sin** middleware. Dentro del archivo, dos grupos explícitos: `Route::middleware('web')` para las pantallas y `Route::prefix('api/v1/<modulo>')->middleware('api')` para la API. Así la API nunca hereda la sesión ni el CSRF del grupo web ([ejemplo](../../modulos/00-arquitectura/03-backend-laravel.md#3-ejemplo-completo-registrar-un-síntoma-hu-1101)) |
| Migraciones | `$this->loadMigrationsFrom(__DIR__.'/Database/Migrations')` |
| *Seeders* | `DatabaseSeeder` llama a los de cada módulo, en el orden que indica cada ficha |
| Pruebas | `phpunit.xml` añade los directorios `app/Modules/*/Tests/Unit` y `app/Modules/*/Tests/Feature` a sus *testsuites*, y `tests/Pest.php` extiende `TestCase` (con `RefreshDatabase` en las de *Feature*) también en `../app/Modules/*/Tests` |

Para no copiar lo mismo 16 veces, `app/Shared/ModuloServiceProvider.php` es una clase base abstracta que hace la carga de rutas y migraciones. Cada módulo la extiende.

**6. Configuración común** (`.env.example` y `config/`):

| Variable o ajuste | Valor | Por qué |
|---|---|---|
| `APP_NODO` | `nave` | Lo valida HU-01.01; aquí solo se declara |
| `APP_LOCALE` / `APP_FALLBACK_LOCALE` | `es` / `en` | Textos en español |
| `config('app.timezone')` | `'UTC'` | Todas las fechas en UTC ([plan §9.2](../plan-de-sprints.md#92-reglas-de-datos)) |
| `DB_CONNECTION` | `mysql` (en local, el MySQL de XAMPP; en los nodos, el del cPanel), con `utf8mb4` y `utf8mb4_unicode_ci` | [Convenciones de base de datos](../../modulos/README.md#7-convenciones-de-base-de-datos). Las pruebas siguen en SQLite en memoria, como trae el *kit* |
| `QUEUE_CONNECTION` | `database` | cPanel no tiene Redis; la cola la procesa el cron (HU-00.04) |
| `SESSION_LIFETIME` | `480` | 8 h (HU-01.01) |
| `SEED_PASSWORD_DEV` | `astrohealth-dev` | Contraseña de los usuarios de prueba en local (HU-01.01) |
| `NODO_REMOTO_URL`, `NODO_REMOTO_TOKEN` | vacíos | Los usa M15 |

En `AppServiceProvider::boot()`: `Model::shouldBeStrict(! app()->isProduction())`, para que en local y en las pruebas falle cualquier carga perezosa o atributo inexistente; `DB::prohibitDestructiveCommands(app()->isProduction())`, para que nadie ejecute `migrate:fresh` en cPanel por error.

**6 bis. Base común de la norma** ([ARCHITECTURE.md](../../modulos/00-arquitectura/ARCHITECTURE.md)). La usan todos los módulos desde el primer día:

| Pieza | Dónde | Qué hace |
|---|---|---|
| `RespuestaApi` | `app/Shared/Http/` | Construye el [sobre JSON](../../modulos/00-arquitectura/ARCHITECTURE.md#12-estándar-json) (`success`, `code`, `message`, `data`, `meta`) con `ok()`, `creado()` y `paginado()`. Los controladores de API responden siempre con ella |
| `CodigoGeneral` | `app/Shared/Http/` | *Enum* con los códigos funcionales comunes (`OK`, `VALIDACION_FALLIDA`, `NO_AUTENTICADO`…) |
| `AsignarTrazaId` | `app/Shared/Http/Middleware/`, global en `bootstrap/app.php` | Da un UUID a cada petición (o usa el del encabezado `X-Traza-Id`), lo añade al contexto del *log* y lo devuelve en el encabezado y en `meta.traza_id` |
| `ErrorDeNegocio` | `app/Shared/Excepciones/` | Clase base de los errores de negocio de los módulos, con su código funcional, su HTTP y, opcionalmente, el campo del formulario al que se refieren |
| Manejador común | `bootstrap/app.php` → `withExceptions` | Toda petición a `/api/*` responde los errores con el sobre de error (`success: false`, `code`, `message`, `data: null`, `errors`, `meta.traza_id`, `meta.modulo` y, solo con `APP_DEBUG`, `meta.debug`). El módulo sale del espacio de nombres de la excepción o del controlador (`App\Modules\Sintomas\…` → `M11`; cada *provider* declara su código) |
| `Transaccion` y `TransaccionMysql` | `app/Shared/Persistencia/` | Abstracción con la que los servicios abren transacciones sin usar `DB::` ([§22](../../modulos/00-arquitectura/ARCHITECTURE.md#22-transacciones)) |
| Páginas de error | `resources/js/pages/Errores/Error.vue`, con `Inertia::render` desde `withExceptions` | `403`, `404`, `500` y `503` en las pantallas, con "Código de seguimiento: <traza_id>" |
| Prueba de arquitectura | `tests/ArquitecturaTest.php` | Las reglas de dependencia entre capas y módulos con `arch()` de Pest ([§19](../../modulos/00-arquitectura/ARCHITECTURE.md#19-testing)). Corre en la CI |
| Límite de tamaño en el frontend | Configuración de ESLint del *kit* | Regla `max-lines` como aviso a partir de 500 líneas ([§18](../../modulos/00-arquitectura/ARCHITECTURE.md#18-límites-de-tamaño)) |
| Documentación de la API | `dedoc/scramble`, solo en desarrollo | Genera la documentación OpenAPI en `/docs/api` (local) a partir de los `Request` y los `Resource` |

**7. Frontend de pruebas.** El *kit* no trae pruebas de Vue. Se instalan `vitest`, `@vue/test-utils` y `jsdom`, con `npm run test` en `package.json` y una prueba de ejemplo. Las usan CI (HU-00.02) y todas las historias de frontend.

**8. README del repositorio.** Requisitos (versiones de PHP, Node y MySQL), instalación en cinco comandos (punto *Criterios*), cómo crear un módulo nuevo y las decisiones del punto 3.

## Criterios de aceptación

- **Dado** un clon limpio, **cuando** ejecuto `composer install`, `npm install`, `cp .env.example .env`, `php artisan key:generate` y `php artisan migrate --seed`, **entonces** termina sin errores y `composer run dev` sirve la página de inicio de sesión.
- **Dado** el proyecto, **cuando** ejecuto `php artisan test`, **entonces** pasan las pruebas del *kit* y las 16 `<Modulo>CargaTest` (cada una comprueba que su *ServiceProvider* está cargado: `app()->getProviders(...)` no está vacío).
- **Dado** el proyecto, **cuando** ejecuto `npm run test` y `npm run build`, **entonces** los dos terminan sin errores.
- **Dado** `php artisan about`, **cuando** lo leo, **entonces** la zona horaria es `UTC` y el idioma `es`.
- **Dado** un módulo con una migración de prueba en `Database/Migrations`, **cuando** ejecuto `php artisan migrate`, **entonces** se aplica sin registrarla en ningún otro sitio.
- **Dado** una ruta de prueba `/api/v1/…` que lanza un `ErrorDeNegocio` de un módulo, **cuando** la llamo, **entonces** recibo `422` con `success: false`, su `code`, `meta.modulo` y `meta.traza_id`, y el mismo `traza_id` está en el encabezado `X-Traza-Id` y en el *log*.
- **Dado** `APP_DEBUG=false`, **cuando** una ruta de la API lanza una excepción no prevista, **entonces** recibo `500` con "Ocurrió un error inesperado." y sin `meta.debug`.
- **Dado** el entorno local, **cuando** abro `/docs/api`, **entonces** veo la documentación generada.
